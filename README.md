# AXI Internship

6-week backend engineering internship progress log.

## Structure
Each `dayXX/` folder contains that day's `app.py`, notes, and screenshots.

## Progress
- Day 1 — Backend Fundamentals: basic Flask server on port 3000.
- Day 2 — REST APIs & Routing: query/path parameters, POST endpoint returning 201 Created.
- Day 3 — In-Memory Database & CRUD Operations: implemented a temporary users database, auto-increment IDs, CRUD (Create, Read, Update, Delete) APIs, and tested endpoints using Postman.
- Day 4 — Real Database (SQLite + SQLAlchemy): schema, migrations, full CRUD against disk-backed storage, verified persistence across restarts.
- Day 5 — Production Readiness: global error handling, modular architecture, linting, edge-case testing, and PR workflow practice.
- Day 6 — Authentication & Password Security: added password_hash to the User model, hashed passwords with bcrypt on registration, built /auth/register and /auth/login with generic 401 errors, and implemented JWT generation (1-hour expiry) on successful login.
- Day 7 — Protecting Endpoints with Auth Middleware: built authenticateToken middleware to verify JWT signatures from the Authorization header, protected GET/PUT/DELETE /auth/me with it, and tested the full matrix — valid token, missing token (401), invalid/expired token (403), and deleted-user-with-valid-token (404).
- Day 8 — Relational Database Modeling & Foreign Keys: designed a One-to-Many relationship between User and Post models, implemented foreign key constraints, performed database migrations, queried related records using SQLAlchemy ORM, and built user-specific API endpoints.
- Day 9 — Input Validation & Security Hardening: implemented request validation using Marshmallow, added XSS input sanitization, confirmed SQL injection protection via SQLAlchemy's parameterized queries, added security headers with Flask-Talisman, and configured rate limiting on the login route with Flask-Limiter.
- Day 10 — Code Refactoring, Comprehensive Testing & Review: reviewed layered architecture, added centralized error handling for 404/500, regenerated requirements.txt, and audited .env files across all days for secrets. Built a PyTest suite with 7 automated tests covering registration, login, XSS sanitization, and rate limiting. Added Swagger/OpenAPI documentation via Flasgger, resolving a Content-Security-Policy conflict between Flask-Talisman and Swagger UI.
- Day 11 — Caching & Performance Optimization with Redis: installed Memurai (Windows-native Redis-compatible server), connected Flask to Redis via redis-py, and practiced core commands (SET/GET/DEL) with TTL expiration. Implemented the Cache-Aside pattern on GET /auth/me with a 5-minute TTL, and added cache invalidation on PUT/DELETE /auth/me so updates are never served stale. Verified caching and invalidation directly via Redis, and noted that response-time differences weren't dramatic on local SQLite since it's already fast for single-row lookups.
- Day 12 — Asynchronous Messaging & Task Queues: implemented a Producer/Consumer pattern using RQ (Redis Queue) built on the existing Redis (Memurai) setup. Registration now enqueues a simulated welcome email job instead of blocking the request. Built a Windows-compatible worker (SimpleWorker) to process jobs independently, added automatic retries (max 3 attempts), and verified failed jobs land in RQ's Failed Job Registry (Dead-Letter Queue). Diagnosed and fixed a Windows-specific "localhost" resolution delay, and measured response times with vs. without the queue to demonstrate the performance benefit.
- Day 13 — Real-Time Communication with WebSockets: integrated Flask-SocketIO for full-duplex, real-time messaging. Implemented connection lifecycle handlers (connect/disconnect/error), room-based event broadcasting, and JWT authentication on the WebSocket handshake with rejection of invalid/missing tokens. Verified multi-client real-time messaging using a browser test client, and documented Redis Pub/Sub as the mechanism for scaling across multiple server instances.
- Day 14 — CI/CD Pipelines & Automated Deployment: built a GitHub Actions pipeline (test -> build-and-push to GHCR -> deploy) with dependency-chained jobs so broken code can't reach deployment. Verified this by opening a PR with an intentional syntax error (build-and-test failed, downstream jobs skipped), then reverting and confirming all checks pass on merge. Deploy stage is fully configured via SSH/GitHub Secrets but not verified end-to-end since no live cloud VM was provisioned for this exercise.
- Day 15 — Observability, Logging & Capstone: added structured JSON logging (python-json-logger) with a per-request correlation ID middleware, rotating file logs to prevent disk exhaustion, and /healthz + /readyz health checks probing SQLite and Redis. Exposed a Prometheus /metrics endpoint for request/latency monitoring. Load tested with Locust (10 users, 0 failures) confirming correlation IDs stayed unique under concurrent traffic, and verified the app recovers cleanly after a simulated crash/restart.
- Day 16 — Advanced Database Indexing & Query Optimization: seeded a 500,000-row table and used EXPLAIN QUERY PLAN (SQLite's equivalent to Postgres's EXPLAIN ANALYZE) to profile slow queries. Built single-column, partial, composite, and covering indexes, cutting a query from 1084ms to 86.88ms. Demonstrated the leftmost-prefix rule and calculated filter selectivity to explain why some indexed queries were still slow. Refactored an unindexed query from 279ms to 14.74ms as the capstone optimization, with results saved as a SQL migration script.
- Day 17 — Asynchronous Processing & Task Queues: extended the existing Redis/RQ setup (from Day 12) with new background jobs, proving the sync-vs-async trade-off directly (3.04s blocked request vs. 31ms enqueue). Added exponential backoff retries and reused the existing Dead-Letter Queue for permanently failing jobs. Load tested by enqueuing 1,000 jobs, and ran a fault injection test — killing the worker process mid-job and confirming a new worker instance automatically resumed the remaining queue, proving RQ's at-least-once delivery guarantee.
- Day 18 — API Security & System Hardening: audited existing SQL/XSS injection safeguards (confirmed sound from Day 9), added CORS restrictions, and migrated rate limiting from in-memory to Redis-backed storage, verified by triggering a real 429 response after 10 rapid login attempts. Added payload size limits, audited full git history confirming no secrets were ever hardcoded, and added automated secret scanning (TruffleHog) to the CI pipeline. Ran a dependency vulnerability scan (pip-audit), finding and resolving 7 known CVEs in pip itself.
- Day 19 — System Design & Architecture Patterns: documented the project's modular monolith structure and compared sync REST vs async pub/sub using the project's own real endpoints. Built a Redis Pub/Sub event publisher/subscriber and demonstrated an explicit database transaction rollback. Diagrammed a high-availability real-time order processing architecture (API gateway, order service, cache, database with read replica, message queue, background workers, WebSocket push), and defended the trade-offs behind database partitioning, caching, and asynchronous queues.
